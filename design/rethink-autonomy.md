# 重新审视：agent 该"自主规划"，不该被框成流程

> 触发：使用中发现 agent 没有自主规划，而是被研究流程框死（每条消息先意图识别→进 research_turn→
> 只允许 8 种研究 act→阶段自动推进…）。本文把整体设计重新拉出来，指出病根并给目标架构。

## A. 现状：我们到底造了什么、每层在强制什么

```
UI：说一句
 └─ 意图识别（我后加的：research/chat 二分）
    ├─ chat → provider.chat（普通回复）
    └─ research → research_turn：
         ├─ ActionProposal 协议：模型只能出 8 种研究 act
         │    (propose_spec / request_run / interpret / ask_user …) —— 不能自己想"要不要查文献/写/跑哪步"
         ├─ policy 裁决 + 审批
         ├─ 阶段状态机 + spec 定稿就自动推进到 ESTIMATION
         └─ budget / health 刹车
 工具（Stata/skill/证据/写稿/审批）全藏在 harness 后面
```

观察：**除了普通 chat 分支，一切"会做事"的路径都被关进一个研究驾驶舱**。模型每轮的任务不是
"用户想干嘛我就干嘛"，而是"从 8 个研究动作里挑一个"。这就是你感觉到的"被框定行为"。

## B. 病根（诚实）

设计初衷是好的：「确定性骨架 + 概率推理」。但落地时我把骨架放错了层：
- 骨架应该约束 **工具副作用与证据可信**（写权分离、可溯源、审批、隐私、幂等、恢复）——这部分是价值，保留；
- 骨架**不应该约束 agent 每步在想什么**（不许闲聊、只能出研究 act、被阶段机推着走）——这部分框死了自主性。

也就是说：我们做成了一个"研究者的驾驶舱"，而不是一个"会研究的 agent"。

## C. 目标架构：一个通用 agent loop + 工具集

```
[用户消息]
   ↓
通用 Agent Loop（LLM + tools，自主任意步数，直到它自己决定停/问/交付）
   ↓  每轮模型自决：回复文本？调用工具？读记忆/文献？跑一段研究？出稿？
  ┌─────────────── 工具集（护栏在工具层，不在外层）──────────────┐
  │ memory/上下文     文献检索(rag)      run_stata(skill)      │
  │ evidence/签卡     写稿(docx)         ask_approval          │
  │ research_state(只读视图)             (更多按需注册)          │
  └───────────────────────────────────────────────────────────┘
   ↓ 每次工具调用：policy/审批/隐私/幂等/写权在"调用时"判定
   ↓ 每一步落 events（trace 就是它到底干了什么的审计）
```

- **聊天是默认状态**，不是特例：模型可以直接回文本，不碰工具。
- **研究只是工具之一**：agent 判断"要验证假设"时才调 run_stata / rag；要不要做、做几步、什么时候问用户，都是它自己规划。
- **阶段/ResearchState/ExperimentFamily** 从"外层流程"降级为 **只读状态与守门条件**：agent 用它判断自己在研究上的位置，但不用它包裹对话。
- **确定性不丢**：写权分离/可溯源/审批硬门/隐私/幂等/恢复/预算健康——都留在工具执行层与事件层，这正是能被面试讲清楚、又不框死自主性的地方。

## D. 迁移（分阶段，内核不动）

1. **会话层重做成通用 loop**：模型可自由回文本；工具按需调用（function-calling 或"自由文本+工具路由"）。
2. **research 收成一组工具/技能**：现有 DID skill + engine + executor 原样复用，只是由 agent 自主触发，而不是外层每句都跑。
3. **护栏上移到工具层**：policy/审批/隐私在 call 时判；Trace 记录 model→tool→result 全链。
4. 阶段/ResearchState 变只读上下文（需要时注入），不再自动推进对话走向。
5. UI 呈现不变：聊天 + 工具产物（表/卡/Word）+ 一条条 Trace。

## E. 仍要保留的"确定性"（别砍）
写权分离 · 证据可溯源 · 审批硬门 · 隐私三档 · 幂等/断点续跑 · 预算与健康刹车 · 技能=方法论文件。
这些是"可信"的来源；自主性在"怎么规划"，可信性在"动工具时被守门"——二者不冲突。

## F. 开放问题
1. 工具调用走**官方 function calling**（更自然）还是继续我们的结构化 proposal+policy？
2. 是否需要"显式计划(plan)"，还是让模型隐式一步步来？（先隐式、用 trace 观察）
3. skill 触发：由模型自主选 vs 检索(rag)触发？
4. UI 的审批/预算/恢复如何表现成"正常对话中 agent 说'我需要你批准 X'"。
