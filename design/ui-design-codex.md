# 实证研究 Agent UI 设计稿（Codex 风格）

> 对应需求：`ui-requirements-codex.md`  
> 设计目标：让研究者在一个 idea 内完成“说清问题 → 看 agent 工作 → 关键处拍板 → 复核证据 → 导出初稿”。界面是工作台，不是数据大屏。

> 视觉稿：`ui-concept-primary.png` 是主工作台唯一视觉基准；`ui-concept-evidence-trace.png` 只规定证据 Sheet 与展开 Trace 的结构。项目级长期约束见 `../DESIGN.md`。

## 1. 设计结论

采用 **单页三层工作台**：

1. 中央“研究对话”是永久主视图，承载消息、结构化结果、审批卡和运行反馈；
2. 右侧“研究检查器”以摘要、证据、运行三个页签呈现当前投影，只读；
3. 底部“Trace 抽屉”按需展开，承担事件过滤、回放和技术核验。

视觉参考 Codex 桌面端：低饱和中性色、细边框、清晰分栏、紧凑工具条、少量状态色。信息密度高，但不做传统后台的卡片瀑布。

## 2. 信息架构与 F1–F7 映射

| 区域 | 核心组件 | 承担需求 |
|---|---|---|
| 顶部工作区栏 | idea 标题、运行态、local_strict、审批计数、导出按钮 | F2、F3、F6、F7 |
| 左侧阶段轨 | 8 个阶段的轻量进度线、当前阶段、完成/阻塞提示 | F2、F7 |
| 中央研究对话 | 用户消息、agent 回合、折叠长文、结果表、证据数字、审批卡、消息输入器 | F1、F3、F5、F7 |
| 右侧研究检查器 | “摘要 / 证据 / 运行”页签 | F2、F5、F6 |
| Trace 抽屉 | 时间线、类型筛选、关键节点、分页/继续加载 | F4、F7 |
| 全局浮层 | 证据详情 Sheet、拒绝/改要求 Dialog、危险动作 Dialog、错误 Toast | F3、F5、F7 |

不提供“直接编辑 phase/spec/claim/event”的入口。所有改变只来自对话、审批、中断、续跑等后端命令。

```text
│ 阶段轨       │ 研究对话                             │ 研究检查器           │

│ ● 研究问题   │ 你                                   │                      │

│ ○ 验证       │ │ [批准] [拒绝并说明] [提出修改]   │ │                      │
│ ○ 写作       │ └──────────────────────────────────┘ │                      │
│              │                                      │                      │
│              │ ┌──────────────────────────────────┐ │                      │
│              │ │ 给 agent 发消息…                 │ │                      │
│              │ │ [附件占位]          [停止][发送] │ │                      │

└────────────────────────────────────────────────────────────────────────────┘
```

推荐宽度：左 176px；中间 `minmax(560px, 1fr)`；右 320px。页面最小可用宽度 1024px。右栏和左栏均可收起，中央对话最大阅读宽度 760px，避免长行。

窄屏（<1024px）隐藏左侧阶段轨，阶段改为顶部横向进度；右侧检查器变为从右滑出的 Sheet。手机端只保证基本查看、发消息与审批，不追求完整三栏。

## 4. 页面与组件规格

### 4.1 顶部工作区栏

- 左：产品名 + idea 名；idea 名超过 28 字截断并可 hover 查看全文。
- 中/右：
  - `本机运行`：盾牌图标 + `local_strict`，tooltip 明确“研究数据与文本不离开本机”；
  - 运行态：`空闲 / 工作中 / 等待你 / 验证中 / 已暂停 / 失败 / 完成`；
  - 待审批数量按钮，点击滚动到最近的未决审批；
  - `生成 Word 初稿` 主次按钮。未满足写作条件时禁用并说明原因。

### 4.2 左侧阶段轨

阶段按产品语义显示：

`研究问题 → 可行性 → 数据准备 → 模型设定 → 估计 → 验证 → 写作 → 完成`

- 已完成：实心圆 + 细实线；当前：深色圆环 + 一行简短状态；未来：空心圆；失败/预算停仅标在当前点，不把整条轨变红。
- 阶段轨是投影展示，不可点击改状态；点击已完成阶段只把对话滚动至该阶段首个事件。

### 4.3 中央研究对话

消息流使用两种视觉语法：

- 用户：淡灰背景的小块，靠右但不做气泡聊天软件感；
- Agent：无大卡片背景，左侧 2px 状态线，标题行包含 actor、时间、阶段和“为什么”折叠按钮。

Agent 回合由可组合 block 构成：

- `SummaryBlock`：首屏只显示 2–4 行摘要，长文默认折叠；
- `ReasoningDisclosure`：展示可供研究复核的理由与假设，不展示内部思维链；
- `ResultTable`：最多首显 6 行，系数等可溯源值使用下划虚线和 link 图标；
- `EvidenceCardMini`：来源、run、指纹摘要；
- `ApprovalCard`：研究闸门或危险动作闸门；
- `RunStatus`：当前命令、耗时、阶段，运行时轻量脉冲；
- `ErrorBlock`：人话说明“停在哪里 / 为什么 / 可以怎么继续”。

输入器固定在中央栏底部：多行 textarea，`Enter` 发送、`Shift+Enter` 换行。agent 忙碌时仍允许发送，新消息文案提示“发送将打断当前步骤”；同时提供独立 `停止` 按钮。停止动作需要短暂 pending 状态，防止重复点击。

### 4.4 审批卡（关键组件）

卡片必须同时回答：

1. Agent 在等你决定什么；
2. 为什么此时必须停；
3. 批准后会发生什么；
4. 拒绝或修改不会丢失什么。

研究闸门样式：蓝灰左边线，标题示例“待你批准 · 冻结主回归设定”。动作：`批准并继续`、`拒绝并说明`、`提出修改`。

隐私/危险动作样式：琥珀色左边线 + 盾牌图标，独立标题“需要权限 · 读取工作区外文件”。禁止与研究闸门共用颜色和措辞。

审批提交后原卡就地变为只读凭证：决定、理由、操作者、时间、对应事件 seq。关页重开仍从 state/events 恢复。

### 4.5 研究检查器

`摘要` 页签：

- 当前阶段与运行态；
- 研究设定：样本口径、因变量、核心解释变量、控制变量、固定效应、聚类层级、识别策略；
- 主 spec：未冻结/`spec_...`；
- 已确认 claims 数量；
- 最近一次健康检查。

字段缺失时显示“尚未确定”，不用 `null`。

`证据` 页签：可浏览 claim/card 列表，支持状态筛选（已确认/待验证/被否定）。每项展示一句 statement、签名状态、引用数量；点击打开证据 Sheet。

`运行` 页签：最近 runs，展示状态、命令摘要、样本量、耗时和关联卡片。失败 run 只显示可读错误摘要，原始输出折叠。

### 4.6 证据 Sheet

由正文里的数值/引文或检查器条目触发，从右侧覆盖检查器展开：

```text
0.038***
数字含义：数字化水平每提高 1 个单位……
来源链：claim_07 → card_12 → run_20260907_04
do 文件：main_fe.do · 第 31–46 行
数据指纹：sha256: 8ce1…94af
环境指纹：Stata 18 / reghdfe 6.12.3 / Windows
[查看本次运行] [复制引用标识]
```

指纹默认截断，复制时取完整值。若链条断裂，醒目标记“未完成溯源”，不允许伪装成可信结果。

### 4.7 Trace 抽屉

- 默认只显示底部 40px 摘要条；展开高度 45–60vh，可拖动。
- 筛选：全部、审批、运行、结论、预算/健康；另提供事件类型搜索。
- 行格式：`#126  approval.granted   researcher   ESTIMATION   14:32:08`。
- `approved / run / claim 签名 / 失败 / budget.limit` 使用不同左侧标记；payload keys 作为折叠详情，不首屏铺开 JSON。
- 初始加载最近 100 条，向上“加载更早事件”；超过 500 条必须后端游标分页或前端虚拟化。

## 5. 关键交互状态机

```text
空闲
 └─发送消息→ 提交中 → 工作中 ─┬─普通回复→ 空闲
                             ├─需要补充→ 等待输入 → 发送消息
                             ├─研究闸门→ 等待审批 ─┬─批准→ 工作中
                             │                    ├─拒绝→ 等待输入
                             │                    └─修改→ 工作中
                             ├─危险动作→ 等待权限 ─┬─允许→ 工作中
                             │                    └─拒绝→ 空闲/替代方案
                             ├─用户停止→ 暂停 → 续跑/新消息
                             ├─预算/健康停→ 暂停 → 续跑/调整后续
                             ├─失败→ 可恢复失败 → 重试/续跑/新消息
                             └─流程结束→ 完成 → 导出 Word
```

状态文案必须包含动作对象，例如“正在校验主回归的样本数”，不只写“加载中”。若状态刷新失败，保留上次成功内容，并在顶部显示“状态暂时未更新”，不清空页面。

## 6. 视觉基调与设计令牌

视觉命题：**像 Codex 的研究工作区，而不是聊天机器人或 BI 看板。**

- 字体：`Inter, ui-sans-serif, system-ui, "Microsoft YaHei", sans-serif`；数字、事件类型、指纹用 `ui-monospace, SFMono-Regular, Consolas`。
- 页面背景：`#F7F7F5`；主工作面：`#FFFFFF`；次级悬停：`#F2F2EF`。
- 主文字：`#1F1F1D`；次级：`#6B6B66`；弱文字：`#8D8D86`；边框：`#E3E3DE`。
- 主动作：`#20201E` / 白字；焦点环：`#6B8AFD`。
- 状态色只在图标、左边线、小标签出现：成功 `#2F7D4A`、等待 `#9A6700`、失败 `#B42318`、信息 `#3D63DD`。
- 圆角：控件 8px、面板 10px、对话结构块 8px；避免 16–24px 的消费级大圆角。
- 阴影：仅 Sheet、Dialog、浮动输入器使用极浅阴影；主要分区用 1px 边框。
- 间距：4 / 8 / 12 / 16 / 24 / 32。正文 15–16px，标签 13–14px，trace 元数据 12px。
- 动效：150–180ms；仅抽屉、Sheet、状态点。尊重 `prefers-reduced-motion`。
- 图标：线性、单色、16–18px；优先常用语义图标，按钮文字不依赖图标理解。

默认只做浅色主题；代码结构预留 CSS token，后续可补深色，不为本轮扩大范围。

## 7. 交互稿：四个必须可见的代表场景

### A. 初始/等待输入

中央显示一条简短引导：“描述研究问题、数据范围，或粘贴现有模型设定。”右侧所有未知字段显示“尚未确定”。禁止用大片插画或营销 hero。

### B. Agent 忙碌

最新回合显示实时状态行、已用时与 `停止`；composer 仍可输入。旧内容保持稳定，不使用整屏 skeleton。

### C. 待批

审批卡在最新 agent 回合中占据视觉焦点；顶部运行态为“等待你”，待审批按钮有计数。批准后卡片原位转为凭证，并追加 trace 事件。

### D. 失败/预算停

错误块标题示例：“主回归未完成”。正文：“Stata 在读取样本时停止；最近完成到数据清洗。你可以从停点续跑，或发送新口径。”动作 `从停点续跑` / `查看相关事件`。不展示 Python 堆栈。

## 8. 前端实现建议

保留 **FastAPI + 原生 HTML/CSS/ES Modules**，本轮不引入 React。理由：当前是单页、数据契约简单，原生实现便于项目作者接手，也避免新增构建链。将现有内嵌 `_HTML` 拆为：

```text
app/src/stata_agent/ui.py              # API 与静态文件挂载
app/src/stata_agent/ui/index.html      # 语义结构
app/src/stata_agent/ui/styles.css      # token、布局、状态与响应式
app/src/stata_agent/ui/app.js          # store、渲染、请求、交互
```

建议用轻量客户端 store 保存最后一次 state/events、当前筛选、抽屉状态；服务端仍是唯一事实来源。所有用户文本用 `textContent` 渲染，禁止拼入 `innerHTML`，避免研究材料触发 XSS。

轮询策略：忙碌 1.5–2 秒，空闲 8–12 秒，页面隐藏时暂停；请求使用 `AbortController` 防止并发堆积。

## 9. 需要新增/调整的后端端点

### 本轮界面必须预留

| 方法与路径 | 用途 | 建议返回 |
|---|---|---|
| `POST /api/approvals/{id}/decision` | 批准、拒绝、提出修改 | `{decision, event_seq, state}` |
| `POST /api/control/stop` | 中断当前运行 | `{status:"stopping", state}` |
| `POST /api/control/resume` | 从最新 checkpoint 续跑 | `{status:"running", state}` |
| `GET /api/draft.docx` | 生成并下载 Word 初稿 | `.docx` 二进制；未就绪返回 409 + 可读 detail |

### 为完整体验建议扩充

| 方法与路径 | 用途 | 设计要求 |
|---|---|---|
| `GET /api/events?limit=100&before_seq=` | Trace 游标分页 | 返回 `{items, next_before_seq}`，替代整表读取 |
| `GET /api/approvals?status=pending` | 恢复持久化审批卡 | 区分 `research_gate` / `permission_gate` |
| `GET /api/claims` | claim 列表与筛选 | 带 status、statement、card_ids |
| `GET /api/cards/{id}` | 证据链详情 | run、do file/line、data/env fingerprint |
| `GET /api/runs/{id}` | 单次运行详情 | status、command、N、duration、readable_error |
| `GET /api/health` | UI 运行健康提示 | 不暴露密钥、路径中的敏感部分 |

`GET /api/state` 建议补充：`idea_title`、`run_status`、`status_detail`、`phase_history`、`research_state` 摘要、`pending_approvals`、`checkpoint`、`draft_ready`、各资源计数。字段仍来自只读物化投影。

## 10. 验收清单

- 首屏能立刻发消息，并同时看到当前阶段、运行态和研究摘要；
- agent 回复内能混排摘要、表格、证据数字、审批卡；
- 忙碌时可停止、可发新消息打断；暂停/失败/预算停均有清晰续跑入口；
- 审批分研究闸门与危险动作闸门，决定提交后成为持久只读凭证；
- 结果数字可打开证据 Sheet 并追到 claim/card/run/do file/指纹；
- Trace 可过滤、折叠、向前分页，500+ 事件不整页渲染；
- Word 未就绪时解释原因，就绪后直接下载；
- 研究文本只发往同源本机 API，无第三方字体、脚本、分析或遥测；
- 键盘可完成发消息、打开/关闭浮层、审批；焦点可见；状态不只靠颜色表达。
