# UI 需求（给 codex 设计，我据此实现）

> **v3 方向（2026-09-08）**：整体设计参考 **codex / deepseek-harness** 的形态。
> 1) 先是**正常 LLM 对话**（研究只是能力，不是主骨架）；
> 2) **多工作区**：左列表 + 主对话，一次只跑一个（类 codex）；
> 3) **研究副产物全部收敛成一条条 trace**——删除 摘要/证据/运行 等 tab 面板；
> 4) **Trace = 单独一页**：右上按钮打开，纯一列事件（`#seq 类型 谁 阶段 摘要`），可搜索/分页；
>    审批、预算/健康、出稿等状态**融进对话**自然呈现（"我需要你确认 X"），不占固定栏。
> 冲突时以本 v3 为准。

## 给 codex 的版式指引（v3 具体化）
- **左侧导航栏 = 一排向下排列的工作区**（类 codex 的会话/线程列）：顶部"新建工作区"；下面每个工作区一项（标题=该 idea 首句/名字），当前项高亮，可切换（未来删除）；**一次只运行一个**。
- **主区 = 纯聊天**：像普通 LLM 产品，不铺研究流程控件；审批以内联按钮/气泡出现。
- **右上/顶栏一个「Trace」按钮** → 单独 Trace 页：一列事件 `#seq 类型 谁 阶段 摘要`，可搜索/分页/过滤，点开看详情（证据卡/do 文件/数值溯源）。
- **版式可借鉴 codex / deepseek-harness**（克制、终端感）；不保留：阶段轨、摘要/证据/运行三 tab 检查器。
- 后端将新增（我在实现期加，设计里注明位置即可）：`GET /api/workspaces`（列表）、`POST /api/workspaces`（新建/命名）、请求带 `?ws=` 切换、`GET /api/trace`（单页 trace，支持 ws/搜索/游标）。

## v2 关键改动
1. **首屏与主交互 = 聊天**：像普通 LLM 产品；研究状态/证据/trace 是**右侧/抽屉的按需面板**，不是左侧主轨。
2. **左侧 = 工作区列表**（多工作区）：每个工作区独立 idea/历史/trace/Word 产物；**同时只有一个在运行**；可新建/切换/（未来）删除；当前工作区在顶栏显示。
3. **不再有"阶段进度条/轨道"主视觉**：阶段、门控、预算/健康状态改为**在对话气泡与状态面板里自然呈现**（agent 该停就说"我需要你确认 X"），不强制让用户看到一列 IDEA→…→DONE。
4. **研究能力按需触发**：agent 认为该判可行性/跑估计/写稿时再做，而不是每步都亮流程；用户也可在消息里说"用 DID 跑一下"来触发。
5. 后端契约不变大：工作区=事件账本的 idea_id；端点加 `?ws=`（默认 ui 兼容）。

> 目的：这不是实现文档，是**需求与约束**。请 codex 输出**界面/交互/信息架构设计**（画稿/结构/字段），评审通过后由我按此写代码（FastAPI + 原生前端，或按你建议的技术栈替换后端契约不变）。
> 后端现状：`app/src/stata_agent/ui.py`（端点见 §5），可改；**契约：UI 只读物化视图 + 发消息，绝不直写事件表/状态**（SPEC §3/§4.4）。

## 0. 一句话

给"实证研究 agent"做一个**研究者看得懂、审得动的对话式工作台**：学者说话 → agent 干活并解释为什么 → 到关键处停下等学者拍板 → 全程能回放、能溯源、能被批准/拒绝/打断，最后能拿到可继续编辑的 Word 初稿。

## 1. 产品上下文（设计要知道的）
- 形态：**单 idea 工作区**的强交互会话（一个研究问题跑到底，别做多任务画布）。
- 角色：学者自己提 idea/数据/文献；agent 是方法顾问 + 执行者（判可行性、跑 Stata、写初稿）。
- 产物：数字/引用全可溯源的中文 Word 实证初稿；研究全过程的 trace。
- 关键心理：**学者要敢信、能复核**——每一步"为什么"要可见；数值不裸信。

## 2. 用户与主场景
- 主用户：会用 Stata 的中文社科/计量研究者（非程序员）。要读得懂中文术语、能快速判断"这里我要不要批准"。
- 场景 A 可行性：学者说想法 → agent 反问/查文献/查数据 → 给"可行/缺什么"，学者补料。
- 场景 B 跑主回归：到 ESTIMATION 主结果 → **停等批准** → 学者批准/要改 spec。
- 场景 C 追溯：学者看到一句"0.038***" → 想点回去看是哪次 Stata 结果。
- 场景 D 中断/续跑：跑到一半学者打断改方向，或进程断了 → 从上次停点继续。

## 3. 功能需求（WHAT，布局与视觉风格由你定）

### F1 对话式工作区
- 主交互 = 对话（学者发消息，agent 回话），但**消息不是唯一形态**：agent 回合里可夹"结构化产物"（表格预览、证据卡、待批问题）。
- 可**打断**（发新消息/按"停"），可让它**继续自动**。
- 长回答要有"看摘要 or 展开"，别整墙塞。

### F2 研究状态面板（侧栏/顶栏）
- 当前**阶段**（IDEA→…→VALIDATION→DONE）与运行态（工作中/等你/验证中/失败）；阶段用**进度式**呈现（不是给研究者压力的大列表）。
- 当前"在用什么"：样本口径/变量/识别策略（ResearchState 摘要）；主 spec 是否已定；已确认结论(claims) 数量。

### F3 门控（最关键的交互）
- agent 到人工门会**停**，UI 要清楚呈现"它在等你决定什么 + 为什么"，给：
  - 批准 / 拒绝（带原因）/ 改成别的要求；
  - 审批要**持久化**（关页面再开还能看到当时请求与决定）。
- 把"研究闸门"与"隐私/危险动作"两类请求分开展示（改样本/换 FE vs 删文件/联网）。

### F4 trace 回放（可折叠抽屉）
- 呈现 agents 的思考/动作/工具/结果时间线：`#seq 类型 actor 阶段`（如 `idea.declared` / `spec.frozen` / `run.succeeded` / `approval.granted` / `budget.limit`）。
- 支持**按类型过滤**、可折叠；关键节点（approved、run、claim 签名）高亮。
- 不是给"日志爬虫"，是给"我信不过，想核对"的人看。

### F5 溯源 / 证据浏览
- 正文/结果里的数字或引文 hover/点按 → 弹出"这张卡"：来自哪次 run、do 文件、data/env 指纹（溯源链）。
- 一次研究的 claims/cards 可列表浏览。

### F6 产出
- "生成 Word 初稿"按钮（下载 .docx）；成果附"引用清单/复现说明"。

### F7 异常与预算提示
- agent 因预算/健康检查停时，明确说"停在哪、为什么、还能续吗（resume）"。
- 出错给可读文案，不吐堆栈。

## 4. 信息架构建议（结构由你排布，这是内容层）
内容都来自两类只读数据 + 一个发消息通道：
1. **state**（当前投影摘要：phase/spec/claims/cards/runs/events 计数）
2. **events**（trace 时间线，只读回放）
3. **chat**（发消息 → 返回 reply + 更新后的 state）
4. Word 下载
**不要**在 UI 引入"编辑研究状态/改事件"的任何控件。

## 5. 后端契约（v0，可随设计微调）
现有端点：
- `GET /`（页面）
- `GET /api/state` → `{phase, spec, claims[], cards[], runs{}, events: N}`
- `GET /api/events?limit=` → `[{seq, type, actor, phase, op, payload_keys}]`
- `POST /api/chat {text}` → `{reply, state}`
如需"审批/批准/拒绝/中断/续跑/下载 Word"，会加对应端点（POST approval、POST resume、GET draft）。**请在设计里为这些交互预留位置并标注它们依赖新增端点**。

## 6. 非功能约束
- **隐私**：研究数据/文献不出本机（local_strict）。无 LLM key 时也能完整用 UI（mock 应答）；**不许**为好看把任何用户文本/数据发第三方。
- **技术栈自由**：你建议（原生/React/Streamlit…），但要能被我接手改码；与后端解耦。
- 中文界面；术语保留英文缩写可加注。
- 桌面为主；事件量大时（>500 条）列表要分页/虚拟化或折叠，别整页卡死。
- 强交互节奏：agent 干活时给"正在做什么"的反馈（哪怕是一行状态）。

## 7. 给 codex 的输出
1. 信息架构 + 页面/组件清单（哪个视图承担 F1–F7 哪几条）。
2. 交互稿（关键页/对话框/状态机：待批、忙碌、失败、等待输入）。
3. 视觉基调建议（勿过度装饰；研究者工具的克制感）。
4. 需要我新增的后端端点清单（对照 §5）。

## 8. 验收（我实现后）
- 学者发一句 → agent 回合结构化产物与回复同屏；到 gate 能批准/拒绝且持久化；
- trace 可过滤回放；结果数字能溯源；
- 断点续跑 / 预算停有明确入口；可下载 Word；
- 全程无研究数据外发。
