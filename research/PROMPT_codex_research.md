## 2. 8 个子系统（逐一做 A/B/C）

1. **Agent 编排与循环**：PydanticAI vs OpenAI Agents SDK vs LangGraph vs Claude Agent SDK vs 自研 loop 的取舍；reAct vs plan-and-execute；**单 agent vs 多 agent 到底什么时候该拆**（我要的证据，不只是感觉）；状态机/图是否必要。
2. **上下文与记忆管理**：业界怎么做长期记忆（mem0 / Zep / MemGPT-Letta / 上下文工程 / RAG-over-own-history / 分层记忆 / 摘要压缩）；"事件溯源(SQLite)即系统记忆 + 需要时检索"这套做法的成熟度与坑；长流程 token/上下文预算的业界做法。
3. **工具调用与结构化输出**：tool-calling 的可靠性问题与业界解法（强制 schema、json mode、重试、并行工具、结果校验）；PydanticAI 的实际优缺；**工具选择**（agent 怎么决定用哪个工具、skill 触发）业界怎么设计。
4. **RAG 与引用接地**：chunking/embedding/向量库/混合检索/rerank/agentic RAG 的 2026 成熟做法；**防幻觉引用/grounding 到具体块**的业界方案；中英混合文档；"双库（文风库 vs 引用库）"有没有先例；几百篇规模下 Chroma+bge-m3 是否合理，还是要换。
5. **安全与 prompt 注入**：Anthropic 的《Building effective agents》/ robust agent 安全指南、OWASP LLM Top 10、guardrails 生态；**"把外部输入当不可信、内容与指令隔离"** 的落地手法（delimiter/系统层隔离/对文献与数据降权）；代码/工具执行的沙箱边界；敏感研究数据不出本机。
6. **可观测与 trace**：LangSmith / Langfuse / OpenTelemetry GenAI 等怎么给 agent 做 trace/成本/评估；我的"事件表 + 自写 UI 回放" vs 现成可观测平台怎么取舍；结构化 trace 的 schema 设计业界惯例。
7. **异常处理与自愈**：LLM/工具/流程三层的业界兜底做法（重试退避/降级/checkpoint/续跑）；"事件表续跑 + 幂等重放" 是否成熟；**质量兜底（validator 不过就不出稿）**在 agent 产品里的先例。
8. **Agent 评测（最重）**：业界 agent eval 现状（promptfoo/Braintrust/DeepEval/OpenAI evals；LLM-as-judge、trajectory eval、task-specific）；**"复现已发表论文当 ground-truth eval"** 有没有先例、怎么定容差与指标；对抗测试（注入幻觉数字/假引用）怎么做成自动化 eval；怎样让"没有标准答案"的评测变得可信可讲。

## 3. 差异化亮点种子（围绕这些挖，但别局限）

- **数值接地 + 可复现闭环**：论文每个数字 → ledger 某次结果 → do-file → 可重跑（Stata 层已给 provenance）
- **复现性是一等公民**：事件表 + provenance + 每次尝试留痕，研究全程可回放
- **领域 ground-truth 评测**：实证研究天然有"标准答案"（已发表论文），这是通用 agent 没有的评测优势
- **研究者视角的全链路 trace + 强交互**（agent 不是黑盒，能解释每一步为什么）
- **skill = 计量方法论文件化**（DID/机制/稳健性可插拔）
- **双文献库职责分离**（学文风 vs 指导变量/引用）

对每个种子：说明它的**稀缺性/为什么难被复制**、业界有没有人做、做成什么样最亮。
